# 盘古：比例回光与施法阶段精度补齐

本轮基线为呈现与公开面板补证提交 `d240abe`，日期为 2026-11-14。前一轮确认了天坠“光能累积增加 25%”和“给予 20 连击”，本轮修正现有整数配置与固定授予阶段无法完整表达这些关系的问题。来源事实保存在 [独立参数记录](acceptance/fighter-pangu-verified-reference-values-20261114.json)；新的机制配置能力仍不构成完整生产预设。

## 1. 用整数余数精确累计比例回光

`HeavenfallRules` 新增可选的 `level6LightChargeRatio`。比例由整数分子、分母和两个显式生命周期策略构成：

| 字段 | 含义 |
|---|---|
| `numerator` / `denominator` | 相对于基础 `lightPerChargeTick` 的总倍率；增加 25% 对应 5 / 4 |
| `carryAcrossCasts` | 是否将不足一个 Light 单位的余数保留到下一次天坠 |
| `discardRemainderAtCapacity` | Light 达到上限时是否清除余数 |

每个实际完成的蓄能区间都计算“基础回光 × 分子 + 先前余数”，用整数除法授予完整单位并保留新的余数。基础每步 1 单位、倍率 5 / 4 时，连续四步授予 1、1、1、2，总计准确为 5；不会每步向下取成 1，也不会每步向上取成 2。乘法与除法使用有界 Int64 计算，非法分母和超出支持范围的配置会被拒绝。

新配置为空时仍使用已有的 `level6LightPerChargeTick`，旧配置与原有测试的整数行为保持不变。只有明确提供比例时才启用新路径。低于六级的角色仍使用基础回光值。

实际施法开始、正常结束和允许的中断按照 `carryAcrossCasts` 处理余数；回合／对局重置无条件清除余数。达到光能上限时按照 `discardRemainderAtCapacity` 处理，其他已确认的回光来源使光能到顶时也执行同一规则。hit-stop 不执行蓄能更新，因此整数值和余数均不会提前增长。

**录像只证明 +25% 总量关系，没有证明原版如何跨施法处理不足一单位的余数。** 两个策略必须由目标配置显式选择，不能将测试中采用的选项当成原版行为。

## 2. 20 连击的授予阶段独立配置

新增可选 `level6ComboGainTrigger`，使用已有的四个阶段入口：接受施法、开始蓄能、实际落地或正常结束。每次施法只会在选定入口授予一次 `level6ComboGain`；中断不会被伪装为正常结束，也不会补发尚未到达的阶段奖励。

该选项为空时保留原先的落地授予行为。Trance 的 `tranceTrigger` 继续独立配置，因此连击与强化状态可以在不同的已确认阶段授予。此次没有假定“使用／激活”的文案一定代表按键当帧或落地帧。

六级面板的 100 连击门槛同时限定原初零冷却和天坠冷却减半，现有门槛逻辑继续保留。固定减少一秒与冷却恢复速度是不同概念；本轮没有给恢复速度加入额外的未经证实加速。

## 3. 攻速叠加增加明确的加法选项

`AttackSpeedStacking` 增加 `additive`，与已有的取较大值和乘法叠加并列。两项 +12.5% 同时有效时，加法结果为 +25%，乘法结果按现有万分位精度取整为 1.2656 倍，取较大值结果为 1.125 倍。无论使用哪种策略，组合后的倍率都必须在引擎可支持范围内。

这只是补齐可表达的策略。当前面板分别确认四级和 Trance 的 +12.5%，没有证明它们在原游戏中如何组合；没有因此改动默认策略或宣布某一种已得到原版验证。

## 4. 回放、兼容与验证

比例参数、生命周期策略、可选连击授予阶段以及运行中的回光余数均进入完整权威编码。回放 schema 升到 **5**，规则版本升到 **9**；新旧版本通过已有的兼容校验区分，不让缺少余数的状态被视作相同。原生画面的瞬时呈现队列仍明确排除在权威编码之外。

旧非盘古目录的四个基准字节长度不变，仅头部版本号更新；具有盘古配置的状态会增加新字段的编码。完整字段顺序见 [当前回放编码说明](fighter-replay-state-encoding.md)。此前记录中的 schema 4 / rules 8 描述的是其当时提交，保留作为历史，不代表当前代码版本。

新增测试覆盖比例余数、跨施法与中断、上限处理、重置、旧配置缺省兼容、四个授予阶段、叠加上限和权威回放差异。另用已核实的六级数字组合进入真实状态分支；其基础属性、动作和未核实策略仍明确标注为合成测试数据。最终执行数量与结果以 [本轮验证记录](acceptance/fighter-pangu-precision-validation-20261114.json)为准。

本轮不修改此前已通过语法解析的原生文件，沿用呈现提交的原生静态复核结果。Linux Swift 核心测试不等同于 Xcode SDK 构建、SceneKit 画面或两台 iPhone 实机验收。

## 5. 仍然保持清楚的边界

原版“防御提高 50%”需要原防御属性和伤害公式，不能填成最终承伤乘 0.5。各技能的暗影、武器、徒手物理百分比需要各自的基础伤害，也不能互相代替。五级正式数值、部分优先级和精确动画时序尚未确认。

盘古源模型、长斧、专属动作、原特效与音频仍未齐备；普通投技接触与自动挣脱演出仍未完成，生产目录继续保持未启用。没有要求用户追加资源，也没有把公开录像中的历史值强称为 11 月客户端的全部当前参数。未执行远程推送、Sites 写入、iOS 构建或 TestFlight 上传。
