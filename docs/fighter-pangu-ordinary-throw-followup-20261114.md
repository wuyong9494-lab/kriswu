# 刘盘古普通投技自动挣脱接入 · 2026-11-14

## 本次完成的代码范围

本次从 `597f6def986ea8a45653fdcce71015bbd4f8ec59` 继续。Sites 仍为第 11 版，远程验收分支仍为 `0d83323a5463b9f3feb57cc00532da2ade5a5c48`。此前 `canBeThrown` 只有查询，没有普通投技在实际接触时调用；本次补齐了配置启用的普通投技、正常目标被投、未接触失败、盘古自动挣脱三条完整战斗分支。

普通投技复用近身方向武器输入。配置中的前／后方向保留各自源动作和双人轨迹；距离较远仍调用普通方向攻击。起手不会冻结目标，接触窗口内重新检查实际距离、前方位置、双方站地、存活、硬控制和目标动作状态。最后一个有效 tick 仍可接触；没有接触则进入明确的收招阶段。

盘古的免投只决定已确认普通投技接触的结果。它不阻止发生接触，也不会被当成“距离不足”；接触后双方进入配置的挣脱动作。挣脱不需要额外按键，不新增网络输入类型，不赋予石化、钉岩或特殊 Boss 抓取的泛化免疫。

## 双人时序、位置与战斗结果

`DuelWeaponThrowRules` 中的来源、距离、接触窗口、动作角色、阶段时长、每个关键帧的源动画相位／位置／朝向、伤害 marker 和倒地时间均须显式提供。现有角色不会自动获得一套猜测参数。配置校验还要求远距普通方向攻击可达、双方所需源动作存在、结束姿势站地、双人相对轨迹能放入竞技场。

成功和挣脱从双方实际接触位置开始。位置由同一权威 tick 采样，源动画相位使用万分比直接驱动，避免双人不同长度动作按整数源帧四舍五入后失步。墙边采用整体平移，保持二人的相对位置；双人阶段内关闭普通身体分离，后投能按给定轨迹越过另一人换边。空抓收招期间目标仍能走动，正常身体分离保留。

成功投技只在配置的伤害 marker 结算一次。倒地持续时间从释放双方时开始，受击、停顿或收招不会重复结算。输入标签不决定伤害类型：伤害种类、盘古倍率、起手风刃、命中连击／光能及双方能量奖励各有明确策略。失败和挣脱阶段的伤害、伤害停顿和倒地值强制为零。

双方同时尝试抓投时，先从共享接触快照判断，再按配置仲裁。可选双方失败或较低 fighter index 优先；后者明确属于应用策略，未经证据不能宣称原版规则。两个角色若声明不同仲裁策略，目录校验拒绝载入。

## 中断和生命周期

- Hitstop 冻结双人位置、源动画和投技阶段；期间按下的攻击不会在挣脱或倒地结束后自动补发。
- 接受的普通受击、石化、钉岩等硬控制会释放抓取关系，随后由真实受击／控制状态接管角色。
- 已经飞出的盘古长矛和风刃继续结算，可以击中投技参与者并解除双人状态。
- 盘古自己成功抓投不会误删之前已结束 Splitter 动作所排程的后续风刃。
- 练习模式先解除 KO 抓取再补回生命；对战回合结束、超时、重置清理投技状态。致死 marker 在落地或释放 tick 时，也提交倒地终姿。

手机与外接屏的“自动挣脱”提示读取真实 `immune` 阶段；诊断画面读取一次性的已接受挣脱事件。界面不推进模拟，也不提供未经验证的盘古原版 FX／音效。

## 确定性和兼容性

回放格式升为 schema 6／rules 10。目录完整编码可选投技规则；动态编码包括双方身份、原点、阶段时钟、接触／伤害一次性标志和释放倒地时钟。派生样本、接触候选及展示事件不另存为游戏状态。

`DuelWeaponThrow.swift` 加入 Python 生成器和原生校验器的必需来源文件列表。现有 wire protocol 仍为 1，双方必须具有相同规则和目录指纹。新测试经过真实选角、加载屏障、host 输入、序列化消息及 guest replay，覆盖两个座位与前／后方向。

本次测试记录见 `acceptance/fighter-pangu-ordinary-throw-validation-20261114.json`；既有 schema 4／rules 8 和 schema 5／rules 9 记录保持历史内容。没有 iOS SDK 的 Linux 环境只能进行 Swift 核心测试和原生文件语法解析，不能据此声称真机双端或 TestFlight 验收完成。

## 来源与尚未核实部分

本次复用了现有缓存，没有要求用户提供新素材，也没有再次下载视频或整包游戏资源。

- [HUY 原作者展示](https://www.youtube.com/watch?v=GNw-4YUvN70&t=200s)，2026-08-25，约 3:20 的原始缓存字幕明确说明盘古会自动脱离对手抓握。它支持普通投技自动挣脱语义；该片段属于测试期展示，不能当作当前正式版的内部配置。后仰画面及单帧 HEAD HIT 不足以证明额外反击伤害。
- [Nekki 官方操作说明](https://nekki.helpshift.com/hc/en/8-shadow-fight-3/faq/170-in-game-controls/) 说明方向与武器／踢击按钮组合产生不同攻击。该文字页没有提供普通投技的专属精确范围、帧数或伤害。
- 现有 Android 1.45.3 动作目录包含六个可核原始字节的通用投技候选；其 `playback_fps` 全为 null，不能把目录帧数直接作为游戏 tick。其他角色命名的 throw-break 动作也不构成盘古挣脱绑定。

详细来源、缓存哈希和限制单列于 `acceptance/fighter-pangu-ordinary-throw-source-audit-20261114.json`。仍缺当前盘古原版模型、专属完整动作／FX／音频、双人投技对应关系与部分正式数值；测试里的 `synthetic_*` 角色和数值只用来验证执行链，不进入生产资源目录。当前已完成的是实际战斗解释器和验证路径，尚不能宣称原版角色外观与所有数值完全复刻。
