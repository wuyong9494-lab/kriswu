# 技能表现与机制深度：制作和验证合同

第三轮研究方案 D；没有修改规则、特效、音频或联网代码。现状依据固定源码 `5b298adf`，视觉观察与来源见[证据台账](arena-quality-evidence-2026-10-30.md)。所有建议值仅供获授权后的原型实验。

## 1. 原版证据 → 当前差距

V02 00:42.09 可见攻击数字、角色血量、脚底阵营标记与暖色墙体并存；V01 约02:03的多人画面也有数字/粒子遮挡。由此提出的目标是让必要信息始终可判断，而不是增加亮度或承诺零遮挡。

当前项目已经有普通弹道、抛射、穿透、冲锋、回旋、召唤、治疗和护盾；不存在“所有人只是同一发子弹”的事实。主要待改善点是：

- `ArenaWorld.makeProjectile` 中部分角色共用亮胶囊/光晕/尾迹；大招金色、强化紫色优先于敌我色，有阵营辨识风险。
- 加法光晕叠加变亮；`explosion` 分支同时发出40+20粒子的两组 burst。单次数量不等于整体GPU开销，必须把覆盖像素、生命周期和并发一起测。
- 模拟即刻产生攻击，动画有自己的时长，缺少被实际验证的统一接触帧合同。
- 普攻统一0.4秒冷却、3弹药；妙具通用9类，许多星徽偏向数值强化。已有机制差异，但可供玩家选择的时机、方向和反制窗口还需专门验证。
- 现有音频有12声部预算，满额时关键音也可能被拒；“事件发生”与“真正听见”不能混为一谈。

## 2. 一次攻击的七段事件时间线

| 阶段 | 必须回答的问题 | 美术/音频合同 | 记录字段 |
|---|---|---|---|
| 前摇 | 是否存在？可移动、转向、取消吗？ | 现有游侠即时攻击不补假前摇；有蓄力的未来机制必须向敌方暴露提示 | input_id、sim_tick、windup_start、cancel_reason |
| 出手 | 哪个模拟时刻扣资源并产生弹道？ | 弩弦释放、枪口闪、起始音效同一语义事件；出手装饰目标≤100ms | release_tick、ammo_before/after、origin/direction |
| 弹道 | 直线、抛射、穿墙、追踪或返程？ | 危险核心清楚，尾迹轻；地面投影不冒充抛物实体 | projectile_id、pos、radius、team、phase |
| 命中 | 墙/人/盾/箱/塔谁先结算？ | 一次判定对应一次核心命中特效；不以粒子碰撞驱动伤害 | hit_id、target、hit_pos、damage/status |
| 受击 | 能动吗？硬控还是纯视觉？ | 轻反应、血量变化、音效有区别；只有规则控制才锁操作 | status_start/end、health_delta、shield_delta |
| 后摇 | 可再次攻击/移动/取消的窗口在哪？ | 动画复位可跨后续逻辑事件，不能把装饰尾巴当硬直 | recover_tick、next_allowed_attack |
| 冷却 | 单个技能、弹药还是额外资源？ | 数字/径向进度/禁用状态一致；满额与接近满额可区分 | cooldown、charges、reload_progress |

这些字段是后续诊断和事件协议建议，不声称当前全有。现阶段先用现有导出、源码事件和录像；若缺字段，按原总清单 B05 请求恢复相应开发授权。

同步目标：同一设备上释放视觉与模拟事件相差不超过一个60Hz呈现间隔作为初期门槛；音效与视觉主瞬态目标约±20ms，需音画同步采集验证。网页播放器录屏、不同设备墙钟都不足以测此门槛。网络状态先区分本地预测、权威确认与远端表现，不用“同时收到包”作为三者同步标准。

## 3. 技能类型的形状、颜色与时序

颜色只承担辅助语义。敌方用连续危险边+外向尖角，友方用较薄边+内侧点段，自身用额外中心记号；实际图形需经过小尺寸测试。黄色/紫色只表达技能强度/强化，**保留阵营边线**。以下时长是装饰生命周期建议，不改变伤害或控制时长。

| 类型 | 出手/飞行/命中 | 地面/状态提示 | 音效与失败反馈 | 多人时保留项 |
|---|---|---|---|---|
| 游侠单发 | 短楔形箭芯、极短尾迹；命中十字/碎片方向沿入射方向 | 瞄准线与真正半径分离；弹芯外围明确危险宽度 | 弦响→破风→软目标/硬墙/盾三种命中；未命中无命中音 | 箭芯、队色边、命中小脉冲；先砍光晕 |
| 连发/散射 | 每发仍独立可见，批次共享短促节奏；不可合成一大片白雾 | 扇形瞄准不表示扇形内每处必受伤 | 一轮节奏有开头/中间/尾声；音量限制不影响每发判定 | 弹芯与批次方向，降低重复尾迹/重复声音 |
| 抛射/范围 | 空中物体、地面落点和阴影分层；落地瞬间一主形 | 预警圈轮廓使用真实半径，填充只表示剩余时间；持续区直到真实结束 | 起抛/落地/持续tick区分；无效落点明确禁止 | 落点边界、倒计时、持续区状态；碎屑最先降级 |
| 近战/突进 | 武器扫弧或前缘，身体仍可见；不留长时间残影 | 规则有预警才画终点；不能凭装饰预告尚未确定的落点 | 前冲、接触、撞墙分开；撞墙不是命中人物 | 主体、真实路径方向、碰撞结果；不保留多重分身 |
| 控制 | 眩晕/减速/击退各有稳定图形，避免同一紫圈表示全部 | 控制剩余时长/免疫反馈；减速不画成完全定身 | 施加与解除各短提示；免疫/无效有独立回应 | 控制类型、持续状态、结束；装饰光点可删 |
| 护盾 | 脚底边+身体局部罩，避免不透明球壳 | 区分百分比减伤、可消耗护盾值、无敌；不可用同图标混称 | 吸收/破裂/自然到期不同声音 | 状态类型与持续/值；内层折射与纹理可删 |
| 治疗 | 朝目标收敛、短上升符号，少量暖绿/青绿色 | 友方范围带阵营图形；有效治疗与过量治疗分开 | 满血无有效治疗用轻提示；不冒出虚假恢复数字 | 有效恢复值、区域边界；持续闪烁可删 |
| 召唤/回旋 | 塔有朝向与攻击读数；回旋去程/返程用不同尾形 | 召唤物归属、生命、期限；返程是否可再命中要可理解 | 新建/替换/销毁分开；去返不靠音高猜 | 实体轮廓、归属、武器方向和真实弹道 |

单个主命中形建议80–120ms，次级碎片120–250ms，余辉200–350ms；范围危险边保持到判定真正结束。高频每秒多次伤害可合并数字展示，但原始伤害事件必须全部保留。合并显示不能把不同目标/治疗伤害混为一条。

## 4. 可读性层级与降级

语义优先级而非硬编码绘制顺序：①将要命中的危险边界/目标区；②自己与敌方主体/足点；③主要弹芯和控制状态；④血量/弹药/必要伤害；⑤尾迹/烟/碎屑/环境装饰。视线遮挡仍按地图规则执行，禁止“为可读性”显示草里不可见敌人。

| 压力级别 | 可用的表现方案 | 不能牺牲 |
|---|---|---|
| 单人展示 | 全主形、次级形和少量尾迹；允许近景观察 | 判定一致、色弱与战斗尺寸验证 |
| 正常6人 | 缩短余辉、合并同目标数字、重复声音节流 | 所有危险弹芯/落点/控制状态 |
| 短时峰值 | 取消装饰光晕、减少碎片、烟低覆盖；环境动态降频 | 不丢攻击，不隐藏敌方预警，不缩小视觉危险范围 |
| 持续热压力 | 经批准后稳定切换更低装饰档，带滞回，记录切换 | 目标帧率/规则/输入节奏；不能每帧反复变档引起闪烁 |

起始压力包络（实验方案）：普通每次命中6–12装饰粒子；大招16–24；全屏装饰存活总数先设192/低档96，按最坏6人同步释放测量调整。这是有界队列设计起点，不是“192必不卡”的结论。所有危险弹道独立于装饰预算，队列满也不能丢失判定或关键提示。

透明覆盖指标：在目标与角色附近截取GPU帧，比较禁用纯装饰前后片元耗时；用1/2分辨率对照判断是否填充瓶颈。可设装饰目标增量 GPU P95≤1.5ms、CPU P95≤0.5ms作为首样板门槛，须在同条件A/B实测。粒子数低也可能因大面积叠层很贵；这两个预算不能与嵌套场景总耗时重复相加。

控制深度来自**可观察承诺→收益→风险→反制→团队互动**。若一个新技能只是同样瞄准、同样释放、同样路径、同样结果而伤害不同，它主要增加数值差异；增加十个按钮也不保证更多有意义的选择。

## 7. 三个候选原型的可执行规则

### R：游侠「定弦」候选（仅将来试验）

保留现有即时普攻（基础射程9、弹速17、半径0.22、1发弹药、0.4s最短攻击间隔、2.0s/发装填）；基础伤害1300只是当前对照，不承诺新平衡。

候选只改变大招：按住后180ms蓄势，释放前可取消；蓄势期间速度为普通的70%、不能普攻；大招仅成功出手时扣满条。按现有穿透重弩效果作为初始结果，不附加眩晕、自动追踪或无敌。取消不发射，200ms内不允许重新蓄势，避免无限闪提示。死亡/眩晕取消；击退是否取消单列A/B，两者不能混测。提示方向在出手前80ms锁定，使对手有明确侧移机会。全部时间是候选，不伪称原版实测。

待验证：180ms是否形成有意义承诺而不是显得迟钝；70%移速是否可被滥用卡走射；与装弹妙具/超充叠加时是否能无缝输出；双机取消与出手资源一致。若失败，先调承诺/反馈，不能直接加伤害掩盖。

### G：骨盾卫「定向护卫」候选

把全向减伤候选改为3秒、面朝方向±60°内60%减伤；侧背不减；期间速度75%、允许普攻但每次普攻暂停护卫150ms。方向随瞄准转动，但转速上限180°/秒，避免瞬间全向免伤。护盾归属为自身，不附加治疗；现有自疗是否保留作为单独版本，禁止一起叠加默认通过。范围视觉画扇形，不能画全身完整无敌球。

按来袭速度与正面法向判断，范围爆炸/持续区明确按“来源→受击中心”方向；无来源环境伤害默认不被方向盾减免，并写进说明。相同tick内死亡优先于新增盾，服务器决定减伤；客户端不自扣两次。关键反制是夹击、等攻击空窗、逼迫转向。

### M：法师「封路余烬」候选

保留越墙抛射，落地后生成2秒、半径1.1格区域；伤害拆为落地与后续tick，**总伤害先与当前一次爆炸相等**以比较机制而不是强度。后续每0.5秒结算；同一个施法者区域重叠只取最大一份持续伤害，多个施法者先设总持续伤害上限供试验；落地爆发仍各自结算。区域不叠加减速，不遮住草的真实显隐规则。

验证落点预警开始时刻与真正到达时刻；贴身、墙后、区域边缘往返；目标已死、施法者死亡后区域是否继续（首版建议继续至期限，所有客户端一致）；三法师阵容是否能消除目标区所有进入机会。若封锁过强，调整空窗/弹药/可进入路线，而不只减持续伤害。

## 8. 所需资源 → 验收方法 → 未知问题

资源：VFX图形设计、3角色动作与事件表、至少8类短音效及墙/盾变体、可复现地图与输入记录、能运行iOS/联网的测试环境。无需购买素材才能先完成这些规格；本轮未制作新素材。

验收至少四组：

1. **判定一致性**：落点内外0.05格递进、射程端点、墙角、箱/塔/盾交叉；画出的“效果半径”与伤害判定的关系写清。当前范围命中含目标半径，不能要求目标中心必须在圈内才受伤；要用碰撞体接触口径验证。
2. **事件可靠性**：一次输入、快速双击、同tick普攻/大招、满弹/满血、死亡/复活、控制中、持球；每事件id只结算一次，丢包/重发不重复伤害或资源消耗。
3. **可读性**：黑白/色弱、暗亮三主题、6人同时技能；5–8人盲测区分敌我/危险种类，错误按原因修，不把特效更亮当改善。
4. **玩法探索**：每候选至少20局小样探索，覆盖三地图、对称换边、同水平真人；记录选择次数、被反制机会、无效技能、死亡原因与主观负担。再扩大样本、按角色/地图/玩家水平分层并报告置信区间。胜率接近50%不等于好玩，少数局赢率不等于平衡。

组合优先测试：护盾×治疗、隐身×持续区、位移×墙/球/箱、召唤×叠加召唤、控制×控制、超充×装填、投掷×草视野、回旋×施法者死亡。先 pairwise 找问题，再对最强组合做完整矩阵，不能宣布已穷尽全部组合。

仍未知：本项目真正输入端到端时延、视觉接触帧、6人最坏透明过绘、玩家是否喜欢候选机制、目标版原版的取消/边界规则。这些均须原型与实测；本文件只做到足以制作试验。
