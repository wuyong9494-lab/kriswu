# 值班工作台验收清单（不涉及游戏）
本地核心测试使用模拟数据。不要为了跑测试把真实人员名单、站名表、发送规则、数传图或招标文件放进仓库或日志。未获外发许可的文件不用真实 API 验收。准备两台设备或一台真机和模拟器时，先核对相同源提交、相同测试数据、发布日期和时区。模拟器通过和 TestFlight 可安装是两件事。

| 流程 | 要看到什么 | 不能算通过 |
| --- | --- | --- |
| 首页 | 在普通日期、交班边界、夜间跨日和排班缺失时，当前排班、下一项提示与数据状态不冲突；首页左上角仍能进入 DeepSeek | 把当天没有数据标成休息；把排班显示成出勤确认 |
| 计划复核 | 清晰计划、黄色警告、站名不匹配、重复和时间冲突；能找到疑点及其源图，保留全量查看 | 无法定位时画一个猜测的框；批量跳过警告；把不同站并入同一组 |
| 发前预览 | 逐组对照接收方、正式任务和附件；改一组不重跑识别、不影响其他组；取消分享无收件人回执 | 系统分享或保存到相册就标“对方已收到”；修改后仍使用旧预览 |
| 交班 | 显示已记录的未完事项、相关排班/计划变化、可确认的后续任务；重启时明确哪些数据只在本次会话中 | 用空列表表示已全部完成；把本机记录当成接班人已经确认 |
| 工作量 | 能点开夜班、节假日、连续在岗日期与来源；数据空档不跨过去；补位同时检查同岗证据及当前/邻日休息，明确需人工确认 | 从缺行推断人有空；把岗位变动直接认定为替班或绩效 |
| 标书 | 微信 PDF / Word 通过系统分享进入本机收件箱；确认上传后逐条核查；核实过的原文和未核实的摘录明显区分；Word 文件可编辑并可再次分享 | 没确认就上传；显示模型编造的位置；把“有响应草稿”当“合规” |

### 计划流程对照记录
每种清晰网页、Excel 截图和含异常的计划至少用一份**脱敏或虚构**样本。固定相同站名表、规则、手机、网络条件，分别在旧版和候选版从导入开始计时，到各组预览准备完为止。记录各组应有文件/条数、实际预览文件/条数、人工改动字段数量和未捕获的问题。先做不发送的演练；只有明确要测试实际微信发给谁时，才用授权的测试会话。切到微信后的收件确认另记，不能拿系统分享状态替代。
