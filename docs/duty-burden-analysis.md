# 近 30 天排班负担
- 入口：值班 App 的「工作量」页。这里看的是已经过去的排班日期与明示岗位，不统计实际工时，不当作个人绩效。
- 不改原有月度工作量、均衡分析或排班预演；不修改排班、提醒、群发送或其他记录。
- 只在本机按已有排班逐日核算。把夜班、法定节假日的实际排班岗位和连续值班分开；遇到未记录日期、班次未分早晚、有冲突的标签或未收录法定节假日，显示数据不足，不把缺失当零或猜测夜班。
- 确认画面：输入模拟值班、空白日、休息、节假日、夜班标记，在工作量页打开新功能，逐项对照明细日期。移除网络后仍可用。不要在 UI 演示或 CI 中使用真实员工资料。
- 当前版本不把任何排班数据发给 DeepSeek，也不生成或提交调班计划。排班建议需要另接明确的资质、可用性、休息间隔与缺岗规则；只看统计不能断言一个调班方案可行。

## 未来 7 天排班复核
- 从「近 30 天值班负担」点「未来 7 天排班复核与岗位变动」。连续三天或以上的已发布在岗日期可逐日检查；缺失、暂定和冲突记录中断连续段。三天是复核提示，不代表违反规定。
- 点单一明确岗位的日期，查看有同岗记录、当日和前后一天都明确为普通休息的同事。90 天同岗证据不等于资质，也不等于本人有空，只能作为向人确认的线索。不处理多个岗位叠加，也不自动联络或调班。
- 同一页显示已保存的岗位人员变化，分别标明岗位日期和同步发现时间。变化本身不能证明是临时替班。
