# 人物成品制作规格：先完成一个可检验的游侠

本规格为第三轮研究建议 D，未制作、导入或替换资产。固定源码和证据等级见 [证据台账](arena-quality-evidence-2026-10-30.md)。目标是一个有独立身份、在大厅与战斗都成立的原创角色；不复制 EVA 角色或宣称达到原版。

## 1. 原版观察证据 → 当前差距

V01 00:00 的 Crow 以鸟头和紧凑躯干辨识，V02 00:00 的 Fang 以宽翼与面部大形辨识。V03 采样中，身体收拢/展开、空中翻转和结束姿态有明显对比。这些说明可见形状和姿态是合理的制作检查项；不提供原版真实面数、头身比例或骨数。

本轮直接看过 `art/ranger/model-combat.jpg`：棕色头发、白色袖子、蓝色披肩、棕靴和横置弩清晰存在；头部小发块密集，弩/手/胸口叠在同一区域，面部与持弩姿势偏对称。它是大幅离线渲染，不能证明正常战斗尺寸下可读。本轮对“需要改”的判断是美术方案，需灰模与真机对照检验。

现有游侠 13,724 三角形、22 关节、一个材质、512 图集、八段动作。问题不是没有模型或完全没有动画，而是缺少完整的表情、姿态、动作衔接和双尺度验收。另有四组共享基础模型，必须分开设计职业轮廓。

## 2. 13 角色：保留、修整与重做边界

下表是**投入建议**。只有游侠离线图在本轮直接视觉复核，其余依据模型映射和职业需求，不冒充全部成品逐帧评审。所有旧基础包可保留作灰盒对照，不以删除旧资源制造“升级”。

| 角色/组 | 可保留 | 为成品辨识需要的工作 | 原因与验收 |
|---|---|---|---|
| 游侠 | 原创源、单位/挂点、部分骨架及已有动作草稿 | 重做头发大形/眼眉嘴关系、手与弩负空间；重调姿态、脚接触与表现曲线 | 自己的首质量样板；实际战斗缩图仍认得弩手 |
| 骑士 / 剑圣 | Knight 灰盒、逻辑接入 | 骑士宽盾重前倾；剑圣长刃与纵向身体，二者至少一套独立主体网格，不能同盔甲换色 | 黑色剪影混排，不能靠名字区分 |
| 蛮王 / 酒桶 | Barbarian 基础移动作验证 | 蛮王上宽下窄、重斧；酒桶圆形主躯干/桶与重心，重新设计投掷与饮用姿态 | 武器、胸腹和移动节奏均不同 |
| 法师 / 书灵 | Mage 灰盒和挂点思路 | 法师尖顶/施法手；书灵展开书页和低重心包围形，调整袖口与手部空间 | 施法者和治疗者在 64–96 像素研究缩图不混淆 |
| 刺客 / 飞镖手 | Rogue_Hooded 基础动作验证 | 刺客窄侧身双刃；飞镖手强调回旋武器及外伸臂，区别兜帽顶形 | 去掉颜色后仍能分组；回旋武器不可遮脸 |
| 骨盾卫 | 骨架基础可复用 | 盾/肩/头外形独立修整，做正面防御和侧背弱点姿态 | 盾宽清楚但不暗示比真实碰撞更宽 |
| 亡灵巫师 | Skeleton_Mage 灰盒 | 非对称法杖、烛火/披肩大形、施法节奏独立设计 | 黑暗主题也要在暗地面分离 |
| 幽影 | Skeleton_Rogue 灰盒 | 低伏/斜向轮廓与闪现前后姿态，减少与刺客重复 | 闪现起终点与真实状态一致 |
| 骨灵 | Skeleton_Minion 灰盒 | 小体型与可识别召唤器，骨塔作为独立伴随资产 | 本体和塔的威胁方向清楚；不是仅缩小骨盾卫 |

“重做”指概念和可见主结构；不要求把可用绑定、文件工具与碰撞规则全部推倒。是否复用拓扑由变形测试决定，不以原文件作者或面数断定质量。

## 3. 代表角色质量合同：原创游侠 R2

角色身份：冷静、敏捷的机械弩巡卫。保留蓝披肩/暖色皮革的世界观连接，以一侧短披肩、三角弩臂和方形靴为识别点。不能挪用原版角色头饰、EVA 胸甲或标志。

以下是探索起始值，不是原版测量结果：

| 项目 | 制作约束 | 检查方法 |
|---|---|---|
| 主比例 | 先比较 2.7/3.0/3.3 头身三种灰模，选一个后锁比例；不靠非均匀缩放导出 | 同镜头正侧背、俯视剪影；对比现有游侠 |
| 轮廓 | 头/躯干/弩三主形；头发归并为 3–5 个方向性块面；一处不对称即可 | 黑色剪影、灰阶和去 UI 图分别识别；禁止拿额外粒子充当职业标志 |
| 脸 | 眉眼朝向和嘴型至少支持平静、专注、受击、胜利四情绪；大眼形与眉弧优先 | 大厅最终尺寸正面/三分之二角，检查眼睛不漂浮、嘴角不穿插 |
| 手脚/武器 | 支撑手与扳机手功能清楚；手指可用合并块面；弩尖和脚尖不相接 | 战斗俯视四主方向和四对角；枪口必须与轨迹一致 |
| 配色 | 大面积冷色与中性色，暖色集中在武器/扣件；建议约 60/30/10 面积起步 | 色弱模拟、灰阶、不依赖红绿判断敌我 |
| 材质 | 皮革/布/金属先通过色块、边缘和局部高光区区分；不用全身同亮度 | 现有 constant 路径截图与离线图并排，不能依赖未导入的金属/法线图 |
| 光照与接地 | 大厅保持脸部明暗和低对比背景；接触阴影跟随脚/跳跃高度；禁止双层厚台抢主体 | 待机、转身、跳跃/死亡逐段检查脚下阴影；不把阴影当作碰撞边界 |
| 实际尺寸 | 先量当前战斗中站立角色像素高 h，再检验 h 与 0.8h；64/96/128px 缩图仅作前置压力检查 | 真机原分辨率不放大看主体、武器、朝向；局部放大仅定位缺陷 |
| 大厅构图 | 探索角色全动作包围盒占可用展示区高 65%–75%；头、武器、胜利动作不碰菜单 | 全动作包围盒并集，不只用 bind pose；适配安全区 |

## 4. 动作与事件合同

现有普攻模拟即时出弹。保留当前机制的美术方案必须在 t=0 放弦，随后后坐/复位；不能为了好看擅自加 150ms 前摇。若未来批准带前摇的新机制，先改机制合同再改动画事件。

| 状态 | 姿态/重心要求 | 建议动作长度及事件 | 衔接与验证 |
|---|---|---|---|
| 大厅入场 | 脚接地后上身整理弩、最后定焦；动作只做一处明确高潮 | 1.0–1.4s 起步；到位/定姿分别标记 | 被切角/开菜单打断无残留；非等待动画完才可操作 |
| 待机 | 重量落在支撑脚，呼吸幅度克制，头有关注方向 | 2.4–3.2s 循环；首尾位置与速度连续 | 30s 循环不跳；与瞄准混合不抖动 |
| 移动 | 8 方向位移与上半身瞄准分离；转向不是整人瞬间扭折 | 以实际速度 v 和步周期 T 验证步长 vT；不固定复制旧比例 | 脚支撑相位滑动目标≤0.05 格，起停/倒退/斜走分别记录 |
| 瞄准 | 持弩稳定，肩与腰有限扭转，越限由下身转向补足 | 不新增隐含攻击延迟 | 每 45° 扫描；武器与攻击方向偏差目标≤3°，需相同坐标系 |
| 普攻 | t=0 出弹；0–67ms 后坐；67–150ms 回弹；150–320ms 回到可瞄准姿态 | 0.32s 与现有重定时一致；出弹点作为契约 | 走射覆盖上身，双脚仍走；能再次攻击与动画尾段分开 |
| 装填 | 有明确装弦/卡扣动作，三发状态不必逐次夸张演 | 先查现有 reload 动作是否真正触发，再拟定播放条件 | 用实际弹药恢复事件驱动；不能动画完成却未补弹 |
| 受击 | 方向性胸肩反应，支撑脚保持；小伤不打断操作 | 80–140ms 主反应，约240ms 恢复起步 | 与后坐叠加不翻转武器；硬控才改变运动规则 |
| 大招 | 更大重心转移与弩臂形变，但保留正面辨识 | 当前参考0.62s；事件点仍由现有模拟定义 | 单独测试移动/墙边/贴身时枪口和命中；新增蓄力另行审批 |
| 死亡 | 倒下主方向、武器归位/消隐顺序清楚 | 当前参考0.8s；死亡状态立即锁定 | 已死不能因 cheer/受击层再次站起；残影不泄露隐身敌人 |
| 胜利/失败 | 胜利展开轮廓，失败收拢；少量表情大于小抖动 | 胜利1.4–1.8s，失败0.8–1.2s 起步 | 中途返回、再来一局状态干净；分别覆盖九状态而非复用一段欢呼 |

接触帧标记采用统一事件名：`release / contact / plant_L / plant_R / recover / death_lock / loop`。这些是将来资产清单字段，当前加载器没有自动消费这些标记的保证。先在研究评审表逐帧对齐，批准实现后才增加运行时契约。

## 5. 完整制作链与退出条件

| 阶段 | 交付物 | 工具/人力 | 通过才进入下一步 |
|---|---|---|---|
| 概念 | 三个剪影方向、正侧背、俯视、四表情、武器功能说明 | 角色概念美术；绘画工具或图像参考辅助 | 选定主形；禁止只有一张精美正面图 |
| 灰模 | 实际镜头灰模、三比例试验、动作最大范围 | Blender；角色/技术美术 | 目标战斗尺寸能认出；通过后才精修 |
| 建模/拓扑 | 可编辑网格、关节环线、清理重叠内面/法线 | 角色美术 | 肩/肘/髋极限姿态不塌；粗轮廓保真 |
| UV/贴图 | 一套不透明主图集、UV间隔、材质分区、源层文件 | Blender 与绘画工具 | 512/1024 对照；mipmap无串色；纹理不承担本该由几何表现的外轮廓 |
| 绑定/权重 | root、躯干四肢、弩挂点；先试少量眼眉/下颌骨 | 绑定师/技术美术 | 每顶点≤4影响作为初始合同；权重归一化；极端动作无穿插 |
| 动画 | 上表动作、8方向走射、事件表、循环检查 | 动画师 | 出手/命中/恢复、脚步和表情均可审；无一次性漂亮动作掩盖循环缺陷 |
| 导出兼容 | glTF/GLB、烘焙LINEAR、单位/轴/命名、源工程与导出清单 | 技术美术 | 不依赖未支持的 morph、PBR 通道、运行时约束或 root motion |
| 引擎调校 | 大厅/战斗两套实际截图、连续录像、材质对照、CPU/GPU差值 | 获授权后的 iOS 开发与真机QA | 无额外延迟/错位；最坏6人场景达性能目标 |
| 评审回修 | 缺陷列表、前后同条件对照、版本号 | 美术负责人+用户 | 关键缺陷清零，用户认可视觉；不是导出成功即通过 |

不要先量产 13 人。首样板通过后，再做近战骨盾卫和投掷法师的适配样板：近战要求扫击轮廓和近身接触清晰；投掷要求手中物、抛物顶点、地面落点三者区分；辅助还需确认治疗不被误认为攻击。

## 6. 有依据的起始预算与升级路径

不存在本轮可确认的原版面数预算或 iPhone 17 Pro Max 硬上限。以下从现有资产与6人场景出发，作为**实验范围**：

| 资源 | 起始范围 | 依据和验证 |
|---|---|---|
| 游侠主体 | 先保持现有13,724三角形做品质对照；另评估6k–9k战斗版本 | 六个现有游侠约82,344主体三角形，另有描边/场景；只有剖析证实几何瓶颈才降面 |
| 大厅 | 单主体约12k–18k试验包络 | 一人近景有细节需求；不是承诺更高面数更好；仍须采GPU |
| 骨架 | 身体22骨为基线，带表情探索28–36；每顶点≤4权重 | 六人变为168–216关节，需比较CPU采样/赋值与GPU蒙皮；骨数仅代理指标 |
| 材质 | 首样板主体1材质；确有必要时最多2作为评审阈值 | 描边/透明/阴影会增加通道；现有旧GLB8–9材质且有隐藏附件，不能直接当帧draw call |
| 纹理 | 战斗512与1024 A/B，大厅先1024 | 1024 RGBA8含完整mip约5.33MiB，512约1.33MiB；六种独立1024图集约32MiB，未计引擎副本和压缩 |
| 动画采样 | 30Hz烘焙+插值为初值 | 0.32s内只有约10个采样间隔，关键事件不得靠最近姿态猜；急变段必要时局部提高密度 |
| 阴影/附件 | 接触阴影一层，披肩用少量骨骼，无实时布料/透明发丝 | 优先解决手脚接地和形状，不引入未验证的透明排序成本 |

当前没看到自动 LOD 选择合同，制作双 LOD 不代表引擎会自动切换。首轮用同模型完成一致性验证；获授权后才决定大厅/战斗按场景选文件或实现 LOD，避免增加隐藏接入工作。

## 7. 验收方法与未知问题

1. 近景：正侧背/四表情/九状态连续录像，检查脸、手、武器和穿插。源模型截图不能代替游戏截图。
2. 正常战斗：固定源码、地图、相机、画幅与角色等级；原尺寸看8方向，武器/朝向可读，生命条不盖住面部核心轮廓。
3. 混战：6人、12次普攻与6次技能短时重叠的压力场景；检查自己、最近敌人、危险边界、目标区。可读性失败即返工，不能只减弱敌方提示。
4. 小样盲测：5–8名不了解设计的人随机识别角色/敌我/危险类型，建议≥90%正确率作为初期门槛；记录样本和错误分布。这是筛查，不是统计证明“人人易懂”。
5. 性能：按[制作计划](arena-production-plan.md)采3次短测+30分钟长测；任何预算都以实际显示与热稳定性复核。

未知：最终美术偏好、目标版原版精确比例、设备像素尺寸、实际GPU成本、面部骨骼在加载器中的全部边界。表情方案、材质风格和双LOD先做小样兼容验证，不能把未验证依赖留到13人制作完以后。
