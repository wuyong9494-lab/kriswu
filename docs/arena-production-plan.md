# 资产路径、工作量、质量验收与真实可行性

第三轮研究交付。此文件安排未来制作，不构成开发/购置/发布授权。用户目前只授权研究和研究文档；恢复代码、制作并导入资产、发布新版本均须确认。

## 1. 结论和范围

**小范围达到同等级的视觉完成度，有可执行路径；当前项目没有证明已达到。** 首阶段选择一个原创游侠成品、两个其它职业的机制灰盒、三张布局不同的地图样板、一套贯通当前菜单的视觉规范及真机测试。先证明这条完整制作链成立，再扩大角色与内容规模。

不能据现有条件承诺整个游戏与《荒野乱斗》一样：原版目标版本仍未锁定，已有设备卡顿/草丛反馈未验证解决，游戏还存在本地好友与真实账号系统的差别。人物精美、机制有深度、地图多样、联网流畅是分别需要验证的目标；一项通过不代替其它项。

制作方案例T01/T02表明角色、美术实现、动画、技术美术与QA是不同工作。本项目应据此安排职责，不把外包工作室规模或营销动画质量直接当成自己的预算依据。

| 优先级/阶段 | 具体产出 | 先决条件 | 通过条件 |

| P1a 技术与美术小样 | 游侠灰模三比例、脸/手/弩修正；骨骼表情与LINEAR导出小样；材质实际对照 | 角色规格、可运行制作软件、批准制作与接入 | 实际引擎里不丢材质/动作；大厅与战斗轮廓可读 |

## 5. 工作量估计：按范围和人日，不按口令次数

估算假设：现有源码和工具可继续使用；一名有经验iOS/图形开发、一名角色/动画美术、一名环境/UI美术可参与，并有兼职音频与测试；每天约6小时有效制作；允许至少两轮修改。这里的“人日”是总劳动量，非已确定的工期或供应商报价。

首阶段范围：**一个角色成品、两个机制灰盒、三张地图样板、现有游戏菜单规范与必要接入、基础音画整合和真机回修**。不包含13角色全部重制、实时账号好友/战队后台、原版全部活动商业系统或原版内容量。

| 工作包 | 人日区间 | 估算依据 |
|---|---:|---|
| 冻结基线、参考补证、资产兼容小样 | 3–5 | 已有审计减少摸底，但表情/材质与设备身份仍需验证 |
| 一个角色概念/建模/贴图/绑定/动画回修 | 12–19 | 5–8概念建模+2–3贴图+5–8绑定动画；不是只替换文件 |
| 代表技能VFX与基础音频调整 | 6–10 | 通用状态、命中差异、混音与时序；大规模重新作曲另计 |
| 三图灰盒、模块环境与迭代 | 12–18 | 每图玩法验证+共用环境工具后再做差异；三张布局样板，A图先定一主题；B/C主题按共用模块适配，独立主题包另估 |
| UI统一设计与已知路径接入 | 14–22 | 关键三页先定型，27路径状态复用；不含新账号后台 |
| 机制灰盒、事件接入、性能/网络修正 | 10–16 | 仅选定机制及已定位问题；未定位的底层问题可能超出 |
| 人工QA、三尺度/长测与两轮回修 | 8–12 | 不能省略；需真实设备、玩家和美术评审 |
| **合计** | **65–102人日** | 区间相加；未加不确定性缓冲 |

另预留约20%协调/未知返工，即约78–122人日。3名核心人员有充分交叠时，日历可先按**6–10周**排首个完整质量样板，再据首周实测修订；有依赖或人员缺席会更长。单人顺序完成约13–21个工作周（未计缓冲）。这些是本研究规划估计，不是Supercell公开工期，也不是质量保证。

13角色全重做不能把首角色耗时简单乘13：成熟管线会减少重复劳动，但不同体型/武器/状态会增加工作。首个角色通过后，用实际工时分别估“复用基础”“结构大改”“全新骨架”三档，再报价/排期。不要先承诺整套全量游戏几天完成。

## 6. 性能预算与真实设备验收

首目标为稳定60Hz体验；120Hz可作为后续单独档位，不能先假定设备支持高刷新就一定能稳定跑高帧率。60Hz的16.67ms是呈现间隔；CPU/GPU可能重叠，不能把两者简单相加，也不能将场景总CPU与其中的骨骼CPU重复相加。

### 建议门槛（不是已取得结果或原版实测标准）

| 指标 | 建议初期门槛/报告项 | 如何测 |
|---|---|---|
| 实际呈现 | 稳态60Hz下未按目标间隔呈现的比例<1%；呈现间隔P99≤33.3ms；>100ms停顿为0 | Instruments显示轨道；记录所有样本和最大值；开局加载另列，不能藏掉 |
| CPU/GPU | 各自P95≤12ms，给突发留余量；与16.67ms目标分别比较 | Game Performance/Metal追踪；报告主线程、骨骼、资源加载、片元耗时 |
| 输入/网络 | 本地输入到首可见响应分布、RTT/抖动、权威回拉距离/次数；不预先虚构改善百分比 | 同钟事件+录像；单人/房主/客户端分开，网络条件记录清楚 |
| 草丛/碰撞 | 每观察身份100次草边往返与墙/箱场景，无非预期显隐跳变、卡死或泄露隐藏目标 | 时间对齐位置、visible、状态与呈现；零次是该测试样本结果，不是全球零bug |
| 运行稳定 | 无崩溃/失步；连续30分钟不出现持续资源增长或不可恢复热降级 | 记录内存曲线和thermal state；峰值稳定与缓存预热分开 |
| 画质增量 | 角色、环境、技能分别A/B；预算详见各规格 | 相同镜头、输入、角色、地图、画幅、渲染分辨率和设备条件 |

P99门槛是底线；通过它也不能忽略用户能感知的连续掉帧或输入卡顿。若设备/系统调度导致难以满足，报告实际分布、选择稳定档位和原因，由用户评审体验目标，不悄悄放宽后宣布通过。

### 固定采集协议

记录Build、完整SHA、机型、OS、屏幕刷新设置、分辨率/画幅、画质档、低电量模式、充电状态、起始电量、热状态、网络类型及RTT。短测每场景120秒、至少3次；冷启动与热启动分开。长测30分钟。先不录屏采性能，再单独录屏对照以识别录屏负担；不得只上传最好的一轮。

场景：大厅静置/切角/滚动菜单；空地持续走；墙/活箱边斜走；草边往返；6人走射；6人集中大招；多人房主/客机各一轮；后台/前台与音频中断。动态条件、随机种子、真实mapID和队伍组成留档。

联网至少两台设备检验交战，三台检验房主离开后的其余两方状态。iPhone17 Pro Max必须是验收机之一。网页录像流畅不能替代本项目触控/联网/热测。

## 7. 品质评分与硬门槛

采用0–4分：0缺失、1占位、2功能完整但显著粗糙、3成品级一致、4优于既定标杆的具体方面。每分必须附同条件画面或测量，不可只有形容词。以下权重只是评审组织方法，不是原版官方标准。

| 项目 | 权重 | 评分证据 |
|---|---:|---|
| 角色轮廓/造型/表情/材质 | 20 | 大厅与真实战斗尺寸、8方向、灰阶/色弱 |
| 动作/事件/打击反馈 | 20 | 连续动作、接触帧、走射、命中/盾/墙的区别 |
| 技能可读性与反制 | 20 | 6人峰值、边界、真人决策和失败机会 |
| 地图视觉与布局差异 | 15 | 三图路径指标、相同角色跨图决策、碰撞一致 |
| 大厅与菜单统一/可用性 | 15 | UI00–UI26状态、操作任务、返回与错误 |
| 声音层次/循环/中断 | 10 | 实际试听、三次完整循环、外放/耳机、混战 |

建议每项至少3分且总体≥3.2/4后才讨论“这批样板达到成品标准”。总分不能抵消硬失败：卡死、显隐泄露、视觉判定误导、无法操作、资源扣错、无授权素材、关键角色/危险不可识别均直接退回。与原版“同等级”还须用户对照实际游玩认可，不能由助手自行给分宣布。
