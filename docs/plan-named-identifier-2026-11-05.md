# 照片编号与名称片段核对

用户明确只能提供照片，无法走 Excel 导入流程。本轮继续处理拍照计划中的编号误识，不宣称照片 OCR 可以保证所有输入 100% 正确。原始业务照片仍保留在私有工作区，不上传公共仓库或 CI。

## 待验证实现

只有照片中明确存在独立的卫星 ID 和卫星名称列，且行的完整开始时间、ASCII 圈号、站名、原格和几何信息齐备时，才提取名称末尾真实读出的混合数字字母片段，例如虚构名称「演示07D星」的 `07D`。名称必须只包含一个“星”且以其结尾；片段不允许由 O/0 替换、编号词库或模糊匹配产生。

当前 ID 已包含该片段时保持原值。否则裁切该行原始编号格，以英文 accurate、关闭语言纠错与 customWords 复识，每页最多 64 次。必须实际读出完整 ASCII 编号，其长度与原 ID 相同，名称片段在新读数中唯一出现，片段之外所有字符与原 ID 完全一致，才采用该完整读数。数字前缀、未被名称覆盖的后缀都不能删改。仅规范比较中的空白和大小写，不设置 O/0、1/L、5/6 字符替换规则。

首轮只使用首选读数。后续待验版本检查同一次请求返回的最多三个完整候选，不增加请求次数；有多个 observation 时仍只连接各自首选读数，不组合候选的字符。所有候选经过同样的原格约束，只有唯一的完整编号得到支持才采用；两个不同编号都满足条件则保留原值。重复空白或大小写形式不算不同编号，保留首个实际候选的原格文字。

名称也是 OCR 读数，因此核对相符不是独立真值证明。补读保留原有全部疑项，另记原 ID；照片编号人工确认要求仍生效，test 不参与，其他行字段不变。单列编号表、名称残缺、重复片段、非 ASCII 候选、前后缀变化均保持原值。

## 只有照片时的使用边界

照片是本轮的输入前提，不要求用户先取得 Excel。拍摄时应放大表格、正对屏幕、分段保留完整列和表头，相邻照片留少量重叠，使用原图文件；先检查数字和字母边缘是否清楚。裁切、放大与复识不能恢复原照片中已经缺失的字形信息。

当前 App 走本机 Apple Vision，聊天中的 JSON 提示词没有接入这条识别链路。提示词中的“结合上下文合理推断”不能作为自动补齐关键字段的依据：卫星编号、圈号、日期时间和通道数值都应保留可追溯的原格证据，读不清时继续待核对。不同日期的同卫星同圈号记录也不能只凭时分秒合并。

验收要区分“自动读对”“人工确认”和“仍无法确认”，核对照片完整行数、关键字段与原图裁条。多次 OCR 一致、格式合法、全部测试通过或可发送错误数为零，都不是所有照片 100% 无误的证明。用户两张真实照片尚未在非公开 iOS 环境实际运行，公开合成样例的结果不能替代这一步。

## 验证要求

- 新增 14 项核心回归，覆盖真实片段条件、完整原格证据、前后缀与数字前缀、合法字母 O、布局与原格一致性、test、元数据与人工确认，以及完整引擎候选的唯一性、歧义拒绝和原格保留。
- 新增 1 项实际 Vision 原生测试，包含清晰编号像素、相邻列干扰、不同前后缀、test、原值已相符和不可用名称。
- 四张既有公开合成全图、冻结真值与全部既有原生断言保持。与已验证的 Build 521 的 188 行最终结果逐字段比较，分别统计错→对、对→错、仍错和无法独立对应的变化，不以测试通过或提示数量作为精度证明。
- 改动在独立分支验证；完整验收通过前不合入已验证主分支，不发布 TestFlight。若没有收益或出现已正确编号被改错，应收紧或撤回方案；不得按真值硬编码修复个别样例。
