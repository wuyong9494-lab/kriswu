# 盘古资源接入修复与剩余验收边界

本次接续基线为 `53e8bd4aab88d56d8d2b6150b4e6db0dfeba5712`。这批修改修复了原生接入链中的实际阻塞，但没有取得新的盘古原版资源，不能据此标记“完整原版还原”或“真机通过”。已发表的 Sites 仍为 v11；既有 TestFlight 705 不包含本批代码。

## 已修复的接入问题

### 资源目录与角色绑定

旧加载器只接受固定双刀／双锤 catalog 的 SHA。新的 `SF3_FighterRelease.json` 由签名 App 的 `FighterAssetReleaseSHA256` 校验值授权；该值来自 `FIGHTER_ASSET_RELEASE_SHA256` 构建设置，默认空值保留旧资源版本。目录中的 JSON、联机对方或资源文件自身不能设置这个信任值。出现新清单却缺少授权校验值时，加载失败。

新清单逐项绑定 catalog、角色模型、bodyID、weaponID、全部动作名、动作源 SHA、bundle、帧数及导出帧率。原始动作帧率可保持未知；不会因为导出为 30 FPS 而自动认定源游戏也是 30 FPS。骨架根修正、个人头部 bind-space 修正及材质剔除／采样设置由各角色明确声明，并验证对应模型中的材质确实存在。既有双刀／双锤的固定修正继续受其原模型 SHA 限制。

目标角色必须使用自包含 GLB。除验证整个文件的 SHA 外，还拒绝未纳入清单的外部 buffer、image URI、无效块边界及不支持的必需扩展，避免两个相同资源指纹的客户端读取不同外部贴图、几何或动画数据。这项限制只针对新目标角色，不改变通用场景加载器。

### 专属刀光

旧 `SF3_SourceTrails.json` v1 的两个旧角色、固定贴图和骨骼规则继续保留。新 v2 由独立文件和 SHA 加载，逐角色验证 model SHA、骨骼名称、源骨骼编号、权重、逆绑定、网格、贴图大小和 SHA，以及显式材质参数。

v2 使用明确的 clip 相位窗口控制可见性，精度为 0–10000；不会继续使用旧武器的运动速度启发式来决定盘古技能刀光。显示从当前权威姿势取样，暂停及重复绘制不会推进窗口；战斗结束、显示开关关闭或进入旧暗影投锤展示时关闭。窗口缺失、重复重叠或不属于目标模型时拒绝加载。

目前新增的刀光 shader 支持范围是明确的 alpha-mask、red/alpha 通道、alpha/add 混合及声明的深度／采样参数；不支持的原版 shader 必须另行实现，不能换成一个看似相近的材质后算通过。原版风刃、石柱、石化等技能粒子资源仍未恢复，诊断线框仍只用于碰撞显示。

### 专属音频与事件相位

旧音频包固定的 10 类、29 个 WAV 不再成为新增盘古音频的入口。盘古使用单独校验的音频清单，必须绑定 `liu_pangu` 及其模型 SHA，逐个文件验证大小和摘要。普通命中、格挡、挥击的三个类别为 `panguHit`、`panguBlock`、`panguWhoosh`。

技能音频可以显式绑定已接受的 `castStarted`、`castPhase`、`attackReleased`、`contact`、`teleported`、`landed`、`ordinaryThrowEscaped` 事件。技能、阶段及命中种类必须准确匹配；空 ability 不是通配符。普通命中不重复进入技能 contact cue，技能／派生风命中也不会额外播放普通斧击或旧锤音效。

攻击释放及命中 cue 还必须明确 `generated`、`empowered`，将招式本体、派生风刃和强化版本分开。回合最后一击产生事件后才进入结算；音频仍消费这个已接受的终结步，随后依靠事件 ID 去重，避免因结算后的状态而漏掉最后一声，也不会在休息步骤重复播放。

音频消费按 frame + sequence 去重；同一个 tick 的两个事件仍是两次事件。同 frame 分批到达不会漏后续事件，暂停时不消费，reset/shutdown 清空记录。未提供原音频的 cue 保持静音。以上是绑定执行能力，不是已经获得原音频或原版事件表的证据。

### 联机资源一致性

新资源清单、目标刀光文件、全部相关贴图、盘古音频清单和 WAV 都进入完整内容指纹。已由其他清单引用的同一个文件只有在路径、大小与 SHA 全部相同时才去重；冲突拒绝加载。原角色资源、控制图、场景和旧公共命中特效保持原有校验。

网络规则指纹同时覆盖新增源码、`App/Info.plist` 与构建设置中的资源清单 SHA。运行时必须核对构建规则中的 SHA 和实际加载清单相同，不允许代码身份与资源授权设置脱节。

同时修复既有旧资源包的计数错误：基础资源实际为 62 项，安装原刀光清单后应为 63 项。旧逻辑始终要求 62，会在完整旧刀光包存在时拒绝联机准备；现在按实际已验证的可选清单计数，相应原生测试也同步覆盖。
