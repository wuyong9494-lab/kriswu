# 大厅与全部已知菜单层级：原创游戏界面规范

第三轮设计文档，未修改 SwiftUI、制作图标或调整运行界面。项目路由依据 `5b298adf` 的 `ArenaLobby/ArenaView/ArenaSeasonView/ArenaStoryView/ArenaMenuComponents`。前轮路由审计继续有效，见[大厅与资产研究](arena-research-lobby-assets.md)。

## 1. 原版观察证据 → 当前差距

V01/V02 00:00实际可见：人物是中央主角；左右入口以图标和短标签组织；角色装备与资源有固定区域；模式卡和主对战按钮靠近。V01约00:06看过活动/模式二级页，主题构图和分组标签延续了游戏风格。没有实际看过这些录像里的商店购买、好友管理、装备三级弹层，不能写成逐页原版对照已全完成。

当前项目已做游戏化边框、按钮压下态、横屏游戏Panel，不能再说“完全没做”。但 `ArenaGamePanel/ArenaTileButton` 与 `ArenaMenuScreen/ArenaMenuCard` 两套视觉规则并存；共有模型、图标来源、数据语义和深层状态还没有一份统一成品合同。好友仅本地名字，“战队”复用同事房间，这属于功能语义差距，不能靠换图标掩盖。

国服 EVA 照片与2026国际服录像分开归档。官方2026商店公告说明入口和目录还在变化，故本文件提出原创结构，未知原版页面明确标记。没有把医院值班模块的表单/卡片作为游戏布局模板。

## 2. 整体视觉与交互规范

下列是可直接供设计出稿的起始 token，均非原版像素拷贝。先出大厅、英雄详情、模式页三张状态稿，通过后延展全部路径。

| 维度 | 规范建议 | 验证 |
|---|---|---|
| 世界观 | 蓝月港主色、暖铜机械细节、原创巡卫角色；主色块+深轮廓+轻微压印边 | 大厅、菜单、关卡、技能图标能判断属于同一游戏 |
| 基础色 | 深蓝底`#13244A`、面板`#20477E`、主行动金`#FFC83D`、危险`#EC5A66`、辅助青`#52D6D0` | 实测对比度；颜色不是状态唯一标志；不照搬这些值当已达标 |
| 描边 | 主要控件2pt深色边、底边3–4pt；标题可细描边，正文不重复重阴影 | 低分辨率不糊；不能因粗边压缩文字可读空间 |
| 圆角/形状 | 主行动轻斜切厚按钮；内容框小圆角；数值徽章圆角更小；避免每块同样胶囊 | 静止去色后仍看出主次；图形装饰不能改变触摸区 |
| 字体 | 可授权中文黑体/现有系统字体起步；标题24–28pt、操作16–18pt、正文14–16pt、附注12–13pt起步 | 长中文、数字翻倍、系统文字放大与安全区；最终按设备画幅回调 |
| 图标 | 同一视角、描边宽度和明暗层级；32px光学检查、触摸框≥44×44pt | 11个现有图标逐一保留来源；SF Symbol仅作临时语义占位/适当系统动作 |
| 状态 | 常规、按下、选中、禁用、锁定、通知、加载、成功、失败全部有明确变化 | 禁用标原因，锁定标条件；不能单靠降低透明度 |
| 动效 | 按下80–120ms，下沉2–3pt；页面160–240ms；奖励主强调400–600ms起步 | 可打断、可减弱，连点不叠加；等待网络不能无限循环无说明 |
| 音效 | 导航短轻声、选中确认、错误轻敲、奖励独立句尾；音乐不因开每页重启 | 静音可完成任务；声音等级不得盖过游戏关键音 |
| 触控/返回 | 所有操作≥44pt热区；关闭/返回位置稳定，手势不能引发双操作 | 左右横屏、系统安全区、单手遮挡、屏幕录制各检查 |

这些 token 不要求复制原版商业化页面，也不把“玻璃越多”作为精美。素材可绘成整块有主题的结构，内容层仍须保持可读。

## 3. 大厅构图合同

以**安全区内可用画幅**归一化，x/y∈[0,1]；不是设备像素。建议顶部信息带 y=0–0.14，角色展示 x=0.24–0.74/y=0.15–0.78，左入口 x=0.02–0.18，右入口 x=0.84–0.98，底部主要操作 y=0.80–0.97。实际最小热区优先，窄画幅折叠次要入口，不能机械等比压缩。

- 背景：低频月亮/城市在角色后方留亮度间隔，建筑不能从人物眼睛/武器后穿出造成轮廓混乱；角色显示区不铺高频霓虹字。
- 平台：接地面属于背景或独立轻薄结构，两者只能有一个主台；脚下柔影随动画变化，不能再次叠厚发光圆环抢主体。
- 人物：全动作包围盒放得下，脸不被装备/通知覆盖。胜利/切角可短时越出静止框，但不能覆盖主操作热区。
- 信息：顶部资源点击去向与资源种类一致；角色等级、奖杯、技能状态围绕角色但不在人物正脸上。
- 底部：左为进度/任务，中为模式与地图摘要，右为唯一最突出的“对战”。模式必须显示真实模式/地图选择条件，不能展示固定缩略图却随机换图无说明。
- 次要页面沿用背景层级和标题框，主题装饰可变化；主体内容不复用值班App“设置列表+普通信息卡”的整页结构。

## 5. 交付清单与状态设计

每页交付：默认稿、锁定稿、无内容稿、加载/错误稿；存在购买/升级则另有余额不足、处理中、成功与重复操作稿。界面动效必须带“触发—持续—可打断—结束状态”说明。

资源包建议：大厅背景分层源文件、平台/接地阴影、11个已用入口图标的统一修整稿、角色肖像框、5类按钮、资源徽章、锁/通知/加载/成功/失败图形、赛季/模式关键图、返回/关闭规则。全部最终使用原创或对应许可素材，不能从原版截图裁图当按钮。

美术稿和数据合同绑定：例如金币不足说明差额、满级不能显示下一等级收益；尚未支持账号好友则不画假在线灯；赛季没有付费购买则不画付费解锁。没有必要让产品界面展示源码、文件格式或GPU术语，诊断页除外。

## 6. 验收方法

1. 路由走查：UI00–UI26逐条记录进入、返回、失败与取消；路径循环一次回到相同状态。快速连点、后台恢复、左右横屏、文字过长分别走查。
2. 视觉对照：先固定当前Build/SHA，按同一画幅拍大厅与所有可达菜单；对照稿只评价本项目自己的规范。原版图单列地区/版本/皮肤/状态，未取得则不打分。
3. 操作测试：5–8位新用户尝试“升级英雄、换技能、选模式、创建房间、关闭音乐、回大厅”；记录首次找到入口耗时和错误路径。建议关键操作2次点击内可到达，例外说明原因；真实账户系统缺失不能用用户熟练度掩盖。
4. 观感评审：角色优先、主操作清楚、背景统一、字体可读、动效可打断。游戏UI风格不等于每页相同卡片，也不等于禁用必要的系统分享与权限交互。
5. 性能：大厅角色动画与菜单滚动分别采帧；切页不重新加载整套角色资源；以实际轨迹验证，不能只看静态设计稿。

## 7. 未知问题与继续条件

当前安装包画面、目标原版全部层级录像、最终字体授权和设计偏好尚未确认。继续研究可完成路由状态设计和来源追溯；原版逐页比对与真机可用性须有相应证据。制作/接入本规范要等待用户确认，不能把文档的“建议UI08地图信息页”写成已实现功能。
