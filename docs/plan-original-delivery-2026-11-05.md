# 原图发送与识别文字分别检查

用户明确：发送的是按站名分组的原照片裁条，不应要求先把卫星编号、圈号、时间等文字全部识别正确。本轮从已验证的 Build 521 产品代码续接，父提交为 `30202a91e4407b62ed7f1d716118c0a7bdf5de24`；未纳入 Build 522—525 的编号补读试验。

## 实际修改

- 发送内容使用明确的原图、重绘图片、文字类型。原图只豁免已知的文字抄录疑项；站名归属、应急、状态、原图行边界、跨页对应及未知类型疑项继续检查。发文字和重绘图片始终使用原来的全字段检查，不受页面「发原图」开关影响。
- 左侧应急仍控制附言；状态为 test 或保留了 test 识别证据的行仍从所有出口排除。状态列内容空白或未匹配已知完整状态时，原图发送需要用户核对，不能把 te5t 当作普通计划。
- 保存原图核对只清除发送规则的疑项，保留编号、日期时间等文字疑项；不补造、改写这些值。记录用户确认过的状态原文，自动读数改变后原确认失效。只有明确编辑状态或已有「不是 test」确认入口才可清除 test 证据。
- 原图列表显示站名和实际照片裁条；文字疑项在编辑页单独展开。发送文字被拦截时进入完整文字核对，不会误用原图核对范围。照片缺少表头、行切片或切片无法解码时，继续拒绝拼图，不切换成重绘表格。
- 原图标题只显示运营商与条数，不采用未经确认的 OCR 日期；完整日期仍在原照片正文。文字和重绘图片标题保持原有逻辑。

本轮未改变 OCR 模型、字段合并、照片行发现和裁切算法，也没有声称站名必然识别正确或不存在漏行。完整识别文字仍供可选的文字发送使用；本轮是按实际输出内容纠正检查范围，不是通过降低文字准确率断言使识图试验变绿。
